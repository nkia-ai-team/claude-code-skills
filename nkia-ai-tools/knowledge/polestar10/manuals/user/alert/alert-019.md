오라클 상세

오라클 상세 화면에서는 오라클의 성능 정보, 구성 정보를 확인할 수 있으며 세션 및 SQL 수행 이력을 상세 분석할 수 있습니다. 성능 메뉴에서는 카테고리(인스턴스, 세션(프로세스), SQL, 메모리, 로그, Storage)별로 성능을 확인할 수 있습니다. 구성 이력에서는 오라클 구성 정보(환경변수, 기동시간, 사용자 목록 등)의 변경 이력을 확인할 수 있으며 현황 정보에서는 환경변수, 사용자, 테이블스페이스, 테이블, 인덱스의 현재 시점 구성 정보를 확인할 수 있습니다. 설정 정보에서는 오라클 접속 정보를 수정하거나 역할 및 담당자 등을 설정할 수 있습니다. 세션 분석 메뉴를 통해 오라클에 수행된 세션의 이력을 분석할 수 있고 Top SQL 분석을 통해 오라클에 수행된 SQL 중 성능 지연이 발생된 SQL을 빠르게 찾고 분석할 수 있습니다. 마지막으로 SQL 성능 분석에서는 Top SQL로 수집된 SQL의 성능 지표를 Scatter 차트에 표시하여 한눈에 Top SQL들의 성능을 확인하고 원하는 SQL을 선택하여 분석할 수 있습니다.

오라클 인스턴스 성능

오라클 인스턴스 성능 화면은 오라클 인스턴스의 전반적인 상태, 성능, 효율성 정보를 조회할 수 있는 화면입니다. 상단에 오라클 주요 백그라운드 프로세스 수와 LISTENER(리스너) 접속 가능 여부가 표시되고 그 밑으로 오라클 주요 성능 지표에 대한 차트와 오라클 Effciency(효율성) 지표에 대한 Gauge 바 목록이 표시됩니다.

> 화면 지표

| PMON     | PMON(Process Monitor) 프로세스는 실패한 사용자 프로세스를 정리하고, 실패한 프로세스가 보유하고 있던 리소스를 해제하는 역할을 합니다. 괄호 안의 개수는 Process monitor 프로세스 개수를 표시하며 해당 개수가 0개인 경우 프로세스가 다운되거나 상태가 이상한 경우입니다. Process Monitor 프로세스는 오라클 내에 1개만 활성화됩니다 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SMON     | SMON(System Monitor) 프로세스는 시스템 레벨의 복구 작업을 수행하고, 인스턴스가 시작될 때 필요한 복구 작업을 처리합니다. System Monitor도 오라클 내에 1개만 활성화됩니다.                                                                                              |
| DBWR     | DBWR(Database Writer)는 Buffer Cache에서 변경된 데이터를 파일에 기록하거나 파일에서 다시 Buffer Cache로 불러오는 역할을 수행합니다. Database writer는 오라클 서버 규모에 따라 1개 이상일 수 있습니다. 따라서 화면에 DBWR 개수가 오라클 설정 개수보다 적다면 해당 프로세스의 이상 여부를 확인하여야 합니다.      |
| LGWR     | LGWR(Log Writer) 프로세스는 Redo 로그 버퍼에 있는 변경된 트랜잭션 데이터를 Redo 로그 파일에 기록하는 역할을 합니다. Log Writer 프로세스는 오라클 내에 1개만 활성화됩니다.                                                                                             |
| CKPT     | CKPT(Checkpoint) 프로세스는 데이터 파일/컨트롤 파일에 체크포인트 정보를 기록하는 역할을 합니다. Checkpoint 프로세스는 오라클 내에 1개만 활성화됩니다.                                                                                                             |
| LISTENER | 리스너 프로세스에 접속 요청 시도가 정상적으로 되는지를 표시합니다. 리스너 프로세스에 접속이 가능하지 않다면 리스너 프로세스나 리스너 프로세스 설정 파일(LISTENER.ORA 또는 TNSName…)을 점검할 필요가 있습니다.                                                                                |

DB Time 누적 Area 차트

DB Time을 CPU 시간과 대기 시간의 누적 Area 차트로 표현한 차트입니다. 이를 통해 오라클이 사용한 시간과 함께 해당 시점 CPU를 많이 사용하였는지 대기 이벤트를 많이 대기하였는지 한눈에 파악 할 수 있습니다.

오라클 Efficiency(효율성) 목록

오라클 효율성 지표 값을 통해 현재 오라클이 효율적으로 잘 운영되고 있는지 확인할 수 있습니다. 또한 효율성 지표를 통해 성능을 평가하고 문제를 진단하는데 유용하게 사용될 수 있습니다. 해당 지표들은 100%일때가 가장 효율적이라고 판단할 수 있으며 비율이 낮을수록 해당 지표의 효율성이 낮다고 판단할 수 있습니다. 특히 버퍼 캐시 적중률, Redo NoWait비율이 매우 낮다면 세션 및 SQL 분석을 통해 원인을 찾고 개선할 필요성이 있습니다.

오라클 세션(프로세스) 성능

오라클 세션 및 프로세스 관련 성능을 조회하는 화면입니다. 상단에 세션 사용률 및 세션 수 현황이 표시되며 하단에 세션 관련 지표의 라인차트와 누적 영역 차트가 표시되고 그 밑으로 현재 수행 중이거나 락 세션 목록이 표시됩니다. 해당 화면에서는 추가적으로 “세션 현황”을 볼 수 있는 화면을 제공하며 세션 현황 화면을 통해 세션이 수행한 SQL 정보, “개별 세션 이력 조회”, “개별 SQL 이력 조회”가 가능합니다. “세션 상세 현황”, “개별 세션 이력 조회”, “개별 SQL 이력 조회”에 대한 상세 내용은 본 매뉴얼의 관련 절을 참조하세요.

![](./images/alert-019/media/image11.png)

▶ \[그림5\] 오라클 세션(프로세스) 성능

세션 사용률 및 세션수 현황

현재 시점 오라클 허용 가능 최대 세션수 및 연결 세션수, 세션 사용률, 엑티브/블록/블로킹 세션수가 표시되며 연결 세션수 카드 우측 상단에 표시되는 아이콘(![](./images/alert-019/media/image12.png))을 선택하면 세션 현황 화면이 표시됩니다. 세션 현황 화면에서는 현재 접속된 모든 세션 목록을 조회하고 분석할 수 있으며 자세한 내용은 “세션 현황 화면”절에서 확인하실 수 있습니다.

![](./images/alert-019/media/image13.png)

▶ \[그림6\] 세션 사용률 및 세션수 현황

총 세션수 누적 영역 차트

오라클 접속 세션수를 5가지 상태(Active/Idle/Background/Blocking/Blocked)로 나누어 누적 영역 차트로 표시합니다. 각 범례를 멀티 선택하여 원하는 범례들 만을 보실 수 있습니다. 특히 전체 세션 대비 Active 세션이 많이 지는 시간대나 Blocking, Blocked 세션수가 있는 시간대는 유의해서 살펴볼 필요가 있습니다.

멀티 지표 라인 차트

오라클 세션 관련 주요 지표(엑티브 세션수, 백그라운드 세션수, 세션 사용률, 블록된 세션수, 블로킹 세션수)를 라인차트로 확인하여 해당 시점 각 주요항목별 이상이 없는 지 빠르게 확인할 수 있습니다. 또한 차트 좌측 상단 콤보 박스를 통해 세션 관련 추가 지표를 차트에 추가하여 비교 조회할 수 있습니다.

구성 변경 이력 조회

구성 이력화면은 오라클의 현재 구성과 과거 구성 값을 항목별로 비교하여 변경 여부를 확인할 수 있는 기능을 제공합니다. 이를 통해 과거 구성 값이 현재 어떻게 변경되었는지 확인이 가능합니다. 또한 비교 목록 우측 상단에 변경 항목 보기 토글 버튼을 클릭하면 변경이 발생된 항목만 표시하여 빠르게 변경 항목 확인이 가능합니다.

![](./images/alert-019/media/image25.png)

▶ \[그림18\] 구성 변경 이력 조회

> 구성 변경 이력 조회 절차

1.  구성 변경 현황 바 차트에서 비교하고자 하는 시점의 바를 클릭

2.  팝업으로 표시된 콤보 박스에서 비교하고자 하는 일자 선택

3.  하단 목록에 항목별로 최신 값과 비교 값이 표시되고 변경된 항목은 변경여부 컬럼에 빨간색으로 표시됨

4.  목록 상단에 변경 항목 보기 토글 버튼을 클릭하면 변경된 항목만 목록에 표시됨

5.  목록 상단에 날자 선택 콤보 박스에서 비교 날짜를 선택하여도 목록에 비교날짜에 해당하는 값이 비교 값에 표시되어 비교할 수 있음

▶ \[그림28\] 상세 설정

> 상세 설정

| 세션 이력 수집 여부  | 세션 이력을 수집할 지 여부를 선택합니다. 세션 이력을 저장하면 세션 분석화면을 통해 세션 분석을 할 수 있습니다.                                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Plan 수집여부    | Plan 정보를 수집할 지 여부를 선택합니다. Plan 정보를 수집하면 Top SQL 분석 및 SQL 분석 화면에서 Plan 정보를 볼 수 있습니다.                                                                                    |
| Top SQL 수집여부 | Top SQL 이력을 수집할지 여부를 선택합니다. Top SQL을 수집 하면Top SQL 분석 및 SQL 분석 화면에서 SQL 이력 분석을 할 수 있습니다.                                                                                |
| Top SQL 수집개수 | Top SQL 이력 저장 시 저장될 Top SQL 개수를 설정합니다. 수집 개수가 많을수록 많은 SQL이 저장되지만 모니터링 대상 데이터베이스에 부하를 줄 수 있습니다.                                                                         |
| 테이블 이력 저장 여부 | 테이블 구성 정보를 저장할지 여부를 선택합니다. 전체 테이블 목록 및 테이블의 상태 등이 구성에 저장되며 추후 구성 이력 비교에서 변경된 정보를 조회해볼 수 있습니다. 단 테이블이 많은 오라클 장비의 경우 조회 부하가 있을 수 있습니다. 단순 모니터링을 하는 경우라면 수집하지 않는 것이 좋습니다. |
| 인덱스 이력 저장 여부 | 인덱스 구성 정보를 저장할지 여부를 선택합니다. 전체 인덱스 목록 및 인덱스의 상태 등이 구성에 저장되며 추후 구성 이력 비교에서 변경된 정보를 조회해볼 수 있습니다. 단 인덱스가 많은 오라클의 경우 조회 부하가 있을 수 있습니다. 단순 모니터링을 하는 경우라면 수집하지 않는 것이 좋습니다.    |

Lock Tree

오라클에 락 세션이 발생되면 Lock Tree 목록에서 해당 락 세션들을 확인할 수 있습니다. Lock Tree에서는 락을 유발한 세션(블로킹 세션)을 부모로 하고 해당 락으로 인해 블록된 세션을 자식으로 하는 트리 형태로 목록을 표시합니다. 부모락 세션을 기준으로 해당 트리를 접거나 펼쳐 볼 수 있으며 SQL ID 컬럼에 있는 SQL ID를 선택하면 하단에 해당 SQL ID에 해당하는 SQL Text가 표시됩니다. SQL Text 창의 우측 상단에 SQL문 포메팅 버튼을 클릭하면 해당 SQL문을 포메팅하여 볼 수 있으며 상세보기버튼을 클릭하면 SQL Text 상세 드로어가 표시되며 해당 드로어 화면에서 SQL에 대한 상세 성능 이력 정보 및 Plan 정보를 확인할 수 있습니다. 자세한 내용은 “개별 SQL 이력 보기(SQL Text 상세 드로어)”절을 참조하세요.

세션 이력 화면을 통해 오라클에 접속한 세션들에 대해 7가지 관점(대기 클래스, SQL, 대기이벤트, 스키마, 프로그램, 호스트, 세션 Lock세션)으로 각 관점 별 수행 SQL과 수행시간, 대기이벤트 정보, Lock 정보 등을 확인할 수 있습니다.

대기 클래스

대기 클래스 관점으로 세션 수행 이력을 분석할 수 있는 화면입니다. 대기 클래스는 세션이 자원을 기다리는 동안 어떤 유형의 대기 상태에 있는지를 분류합니다. 대기 클래스는 대기 이벤트를 여러 범주로 나누어 세션이 전반적으로 어떤 범주의 대기를 하였는지 분석하는데 도움을 줍니다. 대기 클래스에 대한 자세한 내용은 하단 대기 클래스 설명 부분을 참조하세요. 화면 구성은 상단에 해당 대기 클래스를 대기한 세션수가 많은 순으로 표시하는 목록과 도넛 차트가 있고 그 밑으로 타임 셀렉터 기간 동안 세션이 대기한 대기 클래스 수를 누적 바차트로 표시합니다. 바 차트 밑으로는 상세 세션목록과 Lock Tree 목록이 표시되며 세션목록이나 Lock Tree에서 SQL ID 컬럼에 있는 SQL ID를 클릭하면 하단에 해당 SQL ID에 대한 SQL Text가 표시됩니다.

기간별 Top SQL(바차트)

타임 셀렉터 기간에 해당하는 SQL 수행 세션 수를 누적 바차트로 표시합니다. 바차트의 간격은 기간별로 달라지며 바 차트 개수는 최대 60개까지 표현됩니다. 바차트를 1개 선택하면 해당 시점의 바차트만 활성화되고 하단 세션 목록은 바 차트 1개에 해당하는 기간의 세션만 표시됩니다. 따라서 상단에 Top SQL 목록에서 특정 SQL를 선택하고 바차트에서 특정 바 1개를 선택한다면 특정 시점에 선택한 SQL을 수행한 세션들만 세션 목록에서 필터링하여 조회할 수 있습니다.

> Top 대기 이벤트 목록

<table>
<thead>
<tr class="header">
<th>대기 이벤트</th>
<th><p>세션이 대기한 대기 이벤트 이름입니다.</p>
<p>대기 이벤트(Wait Event)는 데이터베이스 세션이 자원을 기다리는 동안 발생하는 다양한 상황을 나타냅니다. 각 대기 이벤트는 특정 유형의 자원 대기를 설명하며, 이를 통해 데이터베이스 관리자는 성능 병목 현상을 분석하고 최적화할 수 있습니다.</p>
<p>대기 클래스 별 주요 대기 이벤트</p>
<p>1. Administrative(관리 작업으로 인해 발생하는 대기) 예시</p>
<p>log file switch (archiving needed): 로그 파일 전환 시 아카이빙 필요로 대기</p>
<p>log file switch (checkpoint incomplete): 체크포인트가 완료되지 않아 로그 파일 전환 대기</p>
<p>2. Application(애플리케이션 코드나 사용자 작업과 관련된 대기) 예시</p>
<p>enq: TX - row lock contention: 트랜잭션의 행 잠금 대기</p>
<p>enq: TM - contention: 테이블 잠금 경합 대기</p>
<p>3. Cluster(RAC 환경에서 노드 간 통신이나 리소스 경합으로 인한 대기) 예시</p>
<p>gc buffer busy acquire: 다른 노드로부터 버퍼 획득 대기</p>
<p>gc buffer busy release: 다른 노드로 버퍼 릴리즈 대기</p>
<p>4. Commit(트랜잭션 커밋 작업을 기다리는 대기) 예시</p>
<p>log file sync: 커밋 시 로그 파일 동기화 대기</p>
<p>log file parallel write: 여러 로그 파일 동시 쓰기 대기</p>
<p>5. Concurrency(동시성 제어 문제로 인한 대기) 예시</p>
<p>library cache lock: 라이브러리 캐시 잠금 대기</p>
<p>library cache pin: 라이브러리 캐시 핀 대기</p>
<p>6. Configuration(데이터베이스 설정 및 구성 문제로 인한 대기) 예시</p>
<p>log buffer space: 로그 버퍼 공간 부족 대기</p>
<p>undo segment extension: 언두 세그먼트 확장 대기</p>
<p>7. Idle(세션이 유휴 상태일때) 예시</p>
<p>SQL*Net message from client: 클라이언트 요청 대기</p>
<p>pmon timer: PMON 타이머 대기</p>
<p>8. Network(네트워크 통신 문제로 인한 대기) 예시</p>
<p>SQL*Net more data from client: 클라이언트로부터 추가 데이터 수신 대기</p>
<p>SQL*Net more data to client: 클라이언트로 추가 데이터 전송 대기</p>
<p>9. Other(특정 카테고리에 속하지 않는 경우) 예시</p>
<p>rdbms ipc message: 인스턴스 간 IPC 메시지 대기</p>
<p>pmon timer: PMON 타이머 대기</p>
<p>10. Scheduler(스케줄러 작업과 관련된 대기) 예시</p>
<p>jobq slave wait: 작업 큐 슬레이브 대기</p>

▶ \[그림72\] 오라클 세션 이력\> Lock 세션

Lock Tree

오라클에 락 세션이 발생되면 Lock Tree 목록에서 해당 락 세션들을 확인할 수 있습니다. Lock Tree에서는 락을 유발한 세션(블로킹 세션)을 부모로 하고 해당 락으로 인해 블록된 세션을 자식으로 하는 트리 형태로 목록을 표시합니다. 부모락 세션을 기준으로 해당 트리를 접거나 펼쳐 볼 수 있으며 SQL ID 컬럼에 있는 SQL ID를 선택하면 하단에 해당 SQL ID에 해당하는 SQL Text가 표시됩니다. SQL Text 창의 우측 상단에 SQL문 포메팅 버튼을 클릭하면 해당 SQL문을 포메팅하여 볼 수 있으며 상세보기버튼을 클릭하면 SQL Text 상세 드로어가 표시되며 해당 드로어 화면에서 SQL에 대한 상세 성능 이력 정보 및 Plan 정보를 확인할 수 있습니다. 자세한 내용은 “개별 SQL 이력 보기(SQL Text 상세 드로어)”절을 참조하세요.

Top SQL 분석

Top SQL 분석 기능을 통해 오라클에 수행된 SQL들 중에 성능 이슈가 있는 SQL등을 3가지 관점(SQL, 스키마, 모듈)으로 분석해 볼 수 있습니다. SQL의 다양한 성능(평균 수행시간, 수행 수, 평균 CPU 시간, 평균 논리 읽기 수, 평균 물리 읽기 수 등) 기준으로, 최대 30개의 Top SQL을 검색하여 분석할 수 있습니다.

SQL

개별 SQL 단위로 성능 지연이 발생한 SQL을 분석할 수 있는 화면입니다. 다양한 성능 지표로 Top SQL을 조회하고 해당 Top SQL의 수행이력을 조회해 볼 수 있습니다. 또한 개별 SQL을 선택하여 한 SQL에 대한 상세 이력 분석이 가능하며 Top SQL 상세 목록에서 Plan Hash 값을 선택하면 상세 실행계획(Execution Plan)을 트리 그리드형태로 확인해 볼 수 있습니다. 또한 개별 SQL에 Plan 이 여려 개인 경우 Plan간 비교 기능도 제공합니다.
