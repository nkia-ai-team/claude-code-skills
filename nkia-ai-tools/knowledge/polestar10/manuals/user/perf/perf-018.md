<span id="_Hlk169177776" class="anchor"></span>애플리케이션 상세

WPM 서비스 타입의 애플리케이션 상세를 확인하고자 한다면 아래의 링크를 클릭합니다.

[► WPM 서비스의 애플리케이션 상세]()

애플리케이션 상세 화면에서는 서비스에서 수행된 애플리케이션의 성능을 조회하고 서비스맵을 통해 에이전트간의 트레이스 처리 현황을 시각적으로 조회할 수 있습니다. 과거에 수행된 애플리케이션을 조회하고자 한다면 \[트레이스조회\]를 선택하고 조회 기간을 지정해 조회할 수 있어 과거에 수행된 응답시간이 느린 트레이스의 실행내역을 상세하게 확인하여 애플리케이션의 문제점을 추적할 수 있습니다. 또한 \[분석\]기능을 통해 애플리케이션의 엔트리포인트, 데이터베이스(쿼리), 예외/에러를 통해 트레이스의 종합적인 성능 상태를 확인 할 수 있어 애플리케이션에서 발생한 성능 문제를 빠르게 조치할 수 있는 분석 데이터를 제공합니다.

성능 \> 서비스 요약

성능의 서비스 요약화면에서는 애플리케이션의 수행 상태를 확인하기 위해 기본적으로 조회하는 주요 지표인 처리건수, 평균응답시간, 에러율, 응답시간에 대한 백분위수에 대한 정보를 제공합니다. 애플리케이션에서 수행 중인 트레이스들의 응답시간과 상태를 시각적으로 빠르게 확인할 수 있도록 응답분포도와 응답시간 히스토그램을 제공합니다.

> 조회 대상 에이전트 변경

1.  > LIVE 모드인 경우 조회 대상에서 선택 또는 제외하고자 하는 에이전트를 클릭.

> LIVE 모드가 아닌 경우 조회 대상에서 선택 또는 제외하고자 하는 에이전트를 클릭하고 조회 버튼 클릭

2.  > 에이전트 전체를 선택하거나 해제할 경우 전체 버튼 클릭

3.  > 에이전트 목록이 한 줄에 표현하지 못할 경우 에이전트 목록의 오른쪽 조회 버튼 앞의 ▼를 클릭하여 전체 에이전트 목록 표시

> ▶ \[그림2\] 상세보기

서비스 요약화면의 평균응답시간, 처리건수, 에러율 지표의 경우 \[상세보기\]를 선택하면 에이전트별 처리현황을 상세하게 확인할 수 있습니다. 지표 상세보기 현황화면에서는 아래의 그림에서 처럼 두 개의 차트가 표시됩니다. 위 차트의 경우 서비스내의 모든 에이전트의 성능을 종합하여 보여주는 차트이며 아래 차트는 개별 에이전트별 성능을 개별 라인으로 보여주는 차트입니다. 첫 번째 차트의 경우 오른쪽 상단의 에이전트 성능을 종합할 때 사용하는 함수를 AVG, SUM, MAX로 변경하여 성능을 확인할 수 있습니다. 개별 에이전트 차트의 경우 현재 시점을 기준으로 Top 5, Top 10, Top 20으로 에이전트별 지표 성능을 확인 할 수 있습니다. 차트 아래의 범례를 선택하여 특정 에이전트를 제외하거나 선택하여 확인할 수 있는 기능도 제공합니다.

응답시간 분포도

애플리케이션 서비스내에서 수행한 트레이스를 응답시간 분포도를 통해 조회할 수 있습니다. 응답시간 분포도는 스캐터 차트를 사용하여 X축은 시간, Y축은 응답시간을 표시합니다. 응답분포도내의 포인트로 표시되는 데이터는 하나의 트레이스를 나타내며 이때 좌표의 X축값은 해당 트레이스의 종료시간을 의미합니다. 응답시간 분포도의 경우 많은 데이터를 표현하기 때문에 조회시간을 변경하여 조회 시 라이브 이외의 조회구간에서는 응답분포도 설정 기능에 따라 최근 5분, 10분 구간만 표시합니다. 5분에서 10분 이상의 데이터를 조회하고자 할 경우에는 서비스 성능\>트레이스조회 기능을 사용하도록 합니다.

![](./images/perf-018/media/image7.png)

> ▶ \[그림4\] 응답분포도

응답분포도를 이용하여 트레이스의 상세 실행내역을 조회하고자 한다면 응답분포도에서 조회 하고자 하는 영역의 포인트를 포함하도록 하여 드래그를 합니다. 드래그한 영역을 포함한 트레이스 현황 화면이 표시됩니다. 응답분포도 내의 노란색 박스가 사용자가 드래그한 영역이며 트레이스 목록에 해당 영역의 트레이스가 표시됩니다. 다른 영역을 조회하고자 한다면 응답분포도의 영역을 드래그 하면 트레이스가 재조회되어 화면에 표시됩니다

성능 \> 트레이스 조회

과거에 수행한 트레이스를 조회하고자 한다면 트레이스 조회 메뉴를 사용하여 과거 수행한 트레이스에 대해 조회할 수 있습니다. \[트레이스 조회\]를 선택하면 기본적으로 최근 15분내에 수행된 트레이스 목록이 표시됩니다. 타임피커를 이용해 조회기간을 변경하여 조회할 수 있습니다. 트레이스 조회에서는 서비스 요약 화면의 응답분포도와 동일한 스캐터 차트가 표시됩니다. 응답분포도에 표시되는 특정영역의 데이터를 조회하고자 한다면 그 영역을 포함하여 드래그를 합니다. 아래 그림에서와 같이 드래그한 영역이 노란 영역으로 표시되며 해당 영역의 트레이스들이 아래 트레이스 목록에 표시됩니다.

예외/에러 관리 화면은 애플리케이션에서 발생한 예외와 에러를 모니터링하고 분석하는 데 사용되는 화면입니다. 이 화면은 특정 예외/에러의 발생 원인과 경로를 추적하고, 문제를 해결하기 위한 정보를 제공합니다. 애플리케이션 목록에서 특정 애플리케이션을 클릭한 후, 분석 \> 예외/에러를 클릭합니다.

서비스맵은 서비스내의 애플리케이션 간의 성능 현황을 시각화하여 표현한 맵입니다. 서비스맵을 통해 애플리케이션 간의 트레이스 처리 현황, 평균응답시간, 에러율을 확인할 수 있으며 알람을 발생했을 경우 발생한 알람을 빠르게 확인할 수 있습니다. 서비스맵의 상단에는 서비스 맵에 다양한 정보를 표현할 수 있는 기능아이콘이 표시됩니다. 서비스맵에서 에이전트는 둥근 노드로 표현되며 외부 리소스의 경우 노드 내 해당 리소스의 아이콘(예:데이테베이스)로 표현됩니다. 본 문서의 서비스맵에서는 에어전트 혹은 외부 리소스 모두 “노드”라는 용어로 통일하여 사용하겠습니다. 외부 리소스는 apm 에이전트가 설치되지 않는 애플리케이션 또는 에이전트가 설치된 애플리케이션과 통신하고 있는 데이터베이스 등을 의미합니다. 노드 간의 선은 두 노드 간의 호출 상태를 알려줍니다. 선의 끝이 둥근 부분이 호출하는 노드, 선의 끝이 화살표인 노드는 호출 대상 노드를 표시합니다.

텍스트 캐시 삭제

WPM에이전트는 수집하는 모든 정보에 대한 텍스트를 UDP로 전송합니다. UDP로 전송 후에는 텍스트는 더 이상 보관하지 않고 전송된 텍스트의 해시코드만 보관합니다. 이런 기능으로 인해 수집서버가 다운되어 있는 상태에서 WPM 에이전트가 텍스트를 수집서버로 전송하면 해당 텍스트는 저장되지 못하고 버려지게 됩니다. 이러한 경우 화면에서 표시되어야 텍스트를 수신 받지 못해 트레이스 정보 등이 해시코드로 표시되는 경우가 발생합니다. 이때 텍스트를 재전송하기 위해 텍스트 캐시 삭제 기능을 사용하면 삭제 이후 수행된 트레이스에 대한 텍스트 정보들이 수집서버로 재전송되게 됩니다.

> 텍스트 캐시 삭제

1.  텍스트 캐시를 삭제하고자 하는 에이전트의 텍스트 캐시 삭제 열의 브러시 아이콘을 클릭하면 에이전트로 텍스트 캐시 삭제 명령어가 전달됩니다.

2.  텍스트 캐시 삭제 명령어 전달 성공 여부는 아이콘 클릭 후 메시지로 표시됩니다.

<tbody>
<tr class="odd">
<td><p><img src="./images/perf-018/media/image3.png" style="width:0.21667in;height:0.21667in" />노트</p>
<p>텍스트 캐시 삭제 명령 전달 이후 수행된 텍스트에 대해서만 재전송됩니다. 만약 텍스트 캐시 삭제 명령 전달 이후 수행되지 않은 URI나 정보에 대해서는 해시코드로 표시될 수 있습니다. 이런 문제를 최소화하기 위해 수집서버가 정상적으로 기동된 후에 애플리케이션을 재기동 해주세요.</p></td>
