# Report Rendering

수집된 데이터를 시트 컬럼별 형식에 맞게 렌더링하는 규칙을 정의합니다.

---

## 1. 입력 데이터 정리

렌더링 전에 수집된 데이터를 **프로젝트 단위로 그룹핑**합니다.

    grouped = {
      "RCA Portal 연동": {
        done: [NKIAAI-414, NKIAAI-413, NKIAAI-380, ...],
        in_progress: [NKIAAI-433],
        commits: { "lucida-chat-ai": [...], "lucida-ui": [...] }
      },
      "RCA Agent": {
        done: [NKIAAI-311, NKIAAI-420],
        in_progress: [],
        commits: { "rca-agent": [...] }
      }
    }

프로젝트가 없는 이슈는 "기타" 그룹으로 분류합니다.

---

## 2. B열 — 업무구분 (금주)

**기본값: `백로그`**

드롭다운 값이므로 시트에 존재하는 값과 정확히 일치해야 합니다.

---

## 3. C열 — 업무 (목표일, 진행율)

이슈를 **번호 리스트**로 나열합니다. 프로젝트가 여러 개일 경우에도 하나의 번호 리스트로 통합합니다.

### 형식

    1. {이슈 제목 요약}
    2. {이슈 제목 요약}
    3. 기타

### 규칙

- 이슈 제목에서 `[AC 요청]`, `[AC 확인]` 접미사 제거
- 제목이 너무 길면(40자 초과) 핵심 키워드로 축약
- Done + In Progress 이슈를 합쳐서 번호 매기기 (Done 먼저)
- 휴가/반차가 있으면 마지막 번호로 추가: `3. 기타`
- 커밋에서 발견되었지만 Linear 이슈에 매핑되지 않는 작업이 있으면 "기타"에 포함

### 예시

    1. RCA 멀티턴 후속 질문 LLM 기반 답변 생성
    2. alarm_select_popup 채팅 인라인 렌더링
    3. RCA 멀티턴 컨텍스트 보강 개선
    4. RCA Agent 서비스 통합 테스트 구축
    5. 기타

---

## 4. D열 — 업무 내용 (상세)

C열의 각 번호 항목에 대한 **상세 내용**을 기술합니다. 이 컬럼이 보고서의 핵심입니다.

### 형식

    1. {이슈 제목}
    - {상세 작업 내용 1}
    - {상세 작업 내용 2}
    - {상세 작업 내용 3}

    2. {이슈 제목}
    - {상세 작업 내용 1}
    ...

### 상세 내용 소스 우선순위

1. **커밋 메시지** — 해당 이슈에 매핑된 커밋의 설명에서 추출
2. **이슈 description의 체크된 AC** — `[X]` 항목에서 달성 내용 추출
3. **이슈 제목** — 위 소스가 없으면 제목만 기술

### 커밋 기반 상세 내용 추출

커밋 메시지에서 의미 있는 변경 사항을 추출합니다:

    # 커밋 메시지 예시
    nkiaai-414 Improve : RCA 멀티턴 후속 질문 시 alarm_select_popup 대신 LLM 기반 답변 생성

    → 추출: "RCA 멀티턴 후속 질문 시 alarm_select_popup 대신 LLM 기반 답변 생성"

동일 이슈의 커밋이 여러 개이면 각각을 서브불릿으로 나열하되, 중복되는 내용은 병합합니다.

### AC 기반 상세 내용 추출

이슈 description에서 체크된 AC 항목을 추출합니다:

    - [X] RCA 분석 완료 후 후속 질문 시 alarm_select_popup 대신 텍스트 답변이 스트리밍되는 것 확인
    → 추출: "RCA 후속 질문 시 텍스트 스트리밍 확인"

AC의 `→ 결과물:` 이후 부분과 코드 블록(```)은 제거하고 핵심 내용만 추출합니다.

### 휴가/반차 반영

캘린더에서 수집된 휴가/반차 이벤트는 "기타" 항목에 포함합니다:

    5. 기타
    - 4/7(월) 오전반차
    - 4/8(화) 연차

### 예시 (전체)

    1. RCA 멀티턴 후속 질문 LLM 기반 답변 생성
    - alarm_analysis 플러그인에 RCA 후속 질문 intent 분류(followup/new_analysis) 추가
    - followup intent 시 alarm_select_popup 대신 conversation context 기반 텍스트 스트리밍
    - 새 알람 분석 요청("다른 알람도 분석해줘") 시 기존 alarm_select_popup 정상 동작 유지

    2. alarm_select_popup 채팅 인라인 렌더링
    - AlarmSelectInline 컴포넌트 구현 (Figma 스펙 2컬럼 레이아웃)
    - useChatStream에 showAlarmSelect 플래그 추가 및 answer_meta 핸들러 연동
    - 대화 히스토리 복원 시 alarm_select_popup 상태 복원

    3. RCA 멀티턴 컨텍스트 보강 개선
    - State 기반 alarm ID 추적으로 불필요한 DB 조회 제거
    - 다중 RCA 지원 (한 채팅방에서 2회 이상 분석 가능)

    4. RCA Agent 서비스 통합 테스트 구축
    - Two-Tier 구조 통합 테스트 설계 및 구현 (Smoke + E2E)
    - Tier 1 smoke test 3/3 PASS 확인

    5. 기타
    - AI Portal 알람 선택 팝업 검색 input border 수정
    - Celery Worker 로그 파일 충돌 해결

## 6. G열 — 차주 업무

다음 사이클 또는 Todo 상태의 이슈를 기반으로 차주 계획을 작성합니다.

### 형식

    1. {이슈 제목}
    - {구체적으로 할 작업}
    - {구체적으로 할 작업}

    2. {이슈 제목}
    ...

### 소스

1. **In Progress 이슈** — 이번 주에 완료하지 못한 진행 중 이슈 (최우선)
2. **Todo 이슈** — 다음 사이클/Todo 상태 이슈
3. **이슈 description** — "목표/기대 결과" 또는 미체크 AC에서 할 작업 추출

### 구체적 작업 내용 추출

- In Progress 이슈: **미체크 AC(`- [ ]`)** 항목에서 남은 작업 추출
- Todo 이슈: **"목표/기대 결과(What)"** 섹션에서 핵심 작업 추출
- 둘 다 없으면 이슈 제목만 기술

### 예시

    1. RCA Agent 서비스 통합 테스트 구축
    - Tier 2 E2E 테스트 안정화
    - run_testbed.sh 전체 PASS 달성
    - 코드 리뷰 완료 및 MR 생성

    2. Bearer Token 만료 대응 로직 추가
    - JWT 토큰 수명 관리 로직 설계
    - mongodb_client.py, polestar_api.py 토큰 갱신 구현

---

## 7. 렌더링 품질 규칙

### 글쓰기 원칙

- **한글로 작성** — 기술 용어(API, MR, JWT 등)는 영문 그대로 사용
- **간결하게** — 서브불릿은 1줄, 불필요한 설명 생략
- **구체적으로** — "기능 개선" 대신 "alarm_select_popup 대신 LLM 기반 답변 생성"
- **동사로 시작** — "구현", "추가", "수정", "설계", "확인" 등

### 분량 가이드

| 컬럼 | 권장 분량 |
|------|----------|
| C열 | 3~7개 항목 |
| D열 | 항목당 2~4개 서브불릿 |
| G열 | 2~4개 항목, 항목당 1~3개 서브불릿 |

### 생략 규칙

- 1 Point 이하의 사소한 수정(typo, 스타일 변경)은 "기타"로 묶기
- 동일 프로젝트의 연관 이슈(예: A 이슈 완료 후 B 이슈에서 후속 작업)는 맥락을 연결하여 기술
- 커밋 메시지가 "WIP", "fix typo" 등 의미 없는 경우 건너뛰기
