# Weekly Report Rendering

수집된 데이터를 주간업무보고 시트 형식으로 렌더링하는 로직을 정의합니다.

---

## 1. 시트 컬럼 매핑

스킬이 채울 컬럼과 생성 방법:

| 열 | 시트 헤더 | 생성 방법 | Section |
|----|----------|----------|---------|
| A | 보고자 | 작성자 이름 | 환경변수 또는 Linear 프로필 |
| B | 업무구분 | `백로그` (고정값) | - |
| C | 업무 (목표일, 진행율) | 이번주 한 일 — 번호 리스트 (요약) | Section 2 |
| D | 업무 내용 | 업무 내용 — 번호 + 서브불릿 (상세) | Section 3 |
| E | 투입시간 | (비워둠) | - |
| F | 업무 구분 | `백로그` (고정값) | - |
| G | 업무 | 다음주 할 일 — 번호 리스트 | Section 4 |

## 2. "업무 (목표일, 진행율)" (C열) — 금주 요약

이번 주 완료/진행한 이슈를 **번호 리스트**로 간결하게 나열합니다.

### 2.1 렌더링 규칙

- 번호는 1부터 순차 부여
- 각 항목은 **이슈 제목에서 핵심만 추출한 한 줄 요약**
- `[AC 요청]`, `[AC 확인]` 접미사는 제거
- 이슈 상태 라벨 (Done, In Progress 등)은 표시하지 않음
- 분류 순서: done → in_review → in_progress

### 2.2 형식

    1. AI Portal 디자인 업그레이드
    2. 도구 선택 API 연동 및 파이프라인 개발
    3. 알람 분석 플러그인 개편 + ITSM 통합
    4. 멀티홉 Thinking/Answer 스트림 분할
    5. 성능 조회 차트/표 렌더링 개발
    6. 기타 UI/AI 개선

### 2.3 이슈 그룹핑

관련 이슈가 여러 개이면 하나의 번호로 묶습니다:

- 같은 기능/주제의 이슈 → 한 줄로 통합
- 단독 이슈 → 개별 번호

소규모 수정 이슈가 2개 이상이면 마지막 번호에 "기타" 또는 "기타 UI/AI 개선"으로 묶습니다.

### 2.4 제목 요약 규칙

- 이슈 제목이 30자 이하: 그대로 사용
- 이슈 제목이 30자 초과: 핵심 키워드만 남겨 30자 이내로 축약
- 기술 용어/고유명사는 축약하지 않음

## 3. "업무 내용" (D열) — 금주 상세

이슈별로 **무엇을 했는지** 상세하게 기술합니다. C열 번호와 1:1 대응합니다.

### 3.1 형식

    1. AI Portal 디자인 업그레이드 (NKIAAI-249)
      - Style Dictionary v5 마이그레이션 및 전체 컴포넌트 디자인 토큰 전환
      - Tooltip 일괄 적용, RCA 컴포넌트 정리

    2. 도구 선택 API 연동 및 파이프라인 개발 (NKIAAI-246)
      - AP 도구 목록 API 구현, UI 동적 로딩 전환
      - AI 도구 선택 고정 파이프라인 라우팅 구현

    3. 알람 분석 플러그인 개편 + ITSM 통합 (NKIAAI-368)
      - 알람 분석 tool_type 분기 및 toolParams 전달 체인 구현 (AI/AP/UI)
      - ServiceRequestPlugin → ITSMPlugin 통합, is_tool_only 패턴 폐지
      - API 스펙 문서 5건 업데이트

### 3.2 렌더링 규칙

- 번호 항목 제목 뒤에 **(NKIAAI-XXX)** 형태로 이슈 번호 표기
- 서브불릿은 `-` (하이픈)으로 시작
- 번호 항목 사이에 빈 줄 하나 삽입 (시트에서 가독성 확보)
- 여러 이슈를 하나의 번호로 묶은 경우 이슈 번호를 쉼표로 나열

### 3.3 서브불릿 작성 규칙

**데이터 소스 우선순위:**

| 우선순위 | 소스 | 추출 방법 |
|---------|------|----------|
| 1 | MR 커밋 메시지 | 커밋 제목에서 이슈번호/Type 접두사 제거 후 사용 |
| 2 | 이슈 description AC 항목 | 체크된 AC에서 핵심 내용 추출 |
| 3 | 이슈 description "목표/기대 결과" | 성과 요약 |
| 4 | 이슈 제목 | 다른 소스가 없을 때 제목만 사용 |

**커밋 메시지 정제:**
- `nkiaai-388 Feat : ` 같은 접두사 제거
- `#117864 Feat : ... nkiaai-367` 같은 UI 형식도 접두사/접미사 제거
- 남은 부분이 서브불릿 내용

### 3.4 이슈별 서브불릿 개수

- 최소 1개, 최대 5개
- 커밋이 5개 초과인 경우 관련 커밋을 의미 단위로 병합하여 5개 이내로 요약
- 단순 이슈(타입 Fix, 작은 수정)는 1~2개로 충분

### 3.5 "기타" 항목

마지막 번호의 "기타" 항목에는 소규모 이슈들을 서브불릿으로 나열합니다:

    6. 기타
    - 이미지 첨부 시 General 강제 라우팅 (NKIAAI-366)
    - PortalMain 컴포넌트 분리, VectorStoreManager 캐시 가드 추가

## 4. "업무" (G열) — 차주 계획

### 4.1 자동 생성 항목

다음 우선순위로 수집합니다:

| 우선순위 | 이슈 상태 | 추출 방법 |
|---------|----------|----------|
| 1 | **In Progress** | 미체크 AC에서 다음 주 작업 범위 추출 |
| 2 | **In Review** | "코드 리뷰 완료 후 머지", "done 처리" 등 |
| 3 | **Todo** | description에서 핵심 작업 내용 추출 |

### 4.2 사용자 입력 (`--next`)

`--next` 옵션으로 전달된 텍스트를 파싱합니다:
- 쉼표로 분리: `"데모 피드백 수정, 완료 리뷰 시연"` → 2개 항목
- 자동 생성 항목 뒤에 추가

### 4.3 형식

    1. 영업팀 AI Portal 데모 및 피드백 수집
    2. 데모 피드백 기반 UI/기능 수정
    3. 완료 리뷰 AI Portal 시연 준비
    4. In Review 이슈 done 처리
      - NKIAAI-246, 249, 292, 366, 367, 368

- 번호 리스트로 작성
- 관련 이슈 번호가 여러 개이면 서브불릿에 쉼표로 나열
- 이슈 번호 없는 항목도 허용 (데모, 미팅 등)

### 4.4 "계속 진행", "착수 예정" 금지

구체적 작업 내용만 기술합니다.

- 금지: `NKIAAI-388 계속 진행`
- 허용: `ChartCard 수정 코드 리뷰 및 머지`

## 5. 렌더링 원칙

### 5.1 팀장 관점

보고서를 읽는 사람은 팀장입니다. 각 이슈를 클릭하지 않고도 이번 주에 무슨 일이 있었는지 파악할 수 있어야 합니다.

### 5.2 실제 데이터 참고

이번 주 시트(20260327 탭)의 기존 팀원 데이터를 읽어서 **문체, 상세도, 형식**을 참고합니다. 다른 팀원들과 일관된 수준으로 작성해야 합니다.

### 5.3 금지 항목

| 금지 | 이유 |
|------|------|
| 상태 라벨 `(Done)`, `(In Progress)` | 보고서에 불필요 |
| AC 진행률 `(AC 2/5)` | 내부 트래킹, 보고서에 불필요 |
| `[AC 요청]`, `[AC 확인]` 접미사 | 이슈 제목 정제 |
| Linear URL | 구글 시트에서 불필요 |
| git 커밋 해시 | 보고서에 불필요 |
| MR 번호 (`!100`) | 보고서 독자에게 불필요 |

### 5.4 줄바꿈 처리

구글 시트 셀 내 줄바꿈은 JSON의 `\n`으로 표현합니다.

    2. 도구 선택 API 연동 및 파이프라인 개발
    3. 알람 분석 플러그인 개편 + ITSM 통합
    4. 멀티홉 Thinking/Answer 스트림 분할
    5. 성능 조회 차트/표 렌더링 개발
    6. 기타 UI/AI 개선

    [업무 내용 (금주 상세)]

      - Style Dictionary v5 마이그레이션 및 전체 컴포넌트 디자인 토큰 전환
      - Tooltip 일괄 적용, RCA 컴포넌트 정리

    2. 도구 선택 API 연동 및 파이프라인 개발 (NKIAAI-246)
    ...

    [업무 (차주 계획)]
    1. 영업팀 AI Portal 데모 및 피드백 수집
    2. 데모 피드백 기반 UI/기능 수정

    ==============================

미리보기 출력 후 `AskUserQuestion`으로 확인합니다:

- **question**: "위 미리보기 내용을 시트에 저장할까요? 수정이 필요하면 내용을 알려주세요."
- **options**: `["저장", "취소"]`

| 응답 | 동작 |
|------|------|
| "저장" 선택 | 시트에 기입 → Step 7 |
| "취소" 선택 | 저장하지 않고 종료 |
| 자유 텍스트 입력 (Other) | 수정 요청 → 해당 부분 수정 후 다시 미리보기 + AskUserQuestion 반복 |
