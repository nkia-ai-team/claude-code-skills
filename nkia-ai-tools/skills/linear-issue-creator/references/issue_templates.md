# Linear 작업 템플릿별 상세 가이드

모든 이슈는 가이드라인의 6섹션 번호 구조를 공통으로 사용합니다.
공통 템플릿 구조는 [guideline-ref.md "이슈 템플릿"](../../_shared/guideline-ref.md) 참조.

작업 유형별로 각 섹션에 어떤 내용을 채워야 하는지 아래에서 안내합니다.

---

## 작업 유형별 섹션 내용 가이드

### 1. 빌드/배포 (Task 타입)

**자동 라벨:** "build"

| 섹션 | 작성 가이드 |
|------|-----------|
| 1. 문제/배경 | 왜 이 빌드/배포가 필요한지 |
| 2. 목표/기대 결과 | 무엇을 빌드/배포하는지, 대상 환경 |
| 3. 완료 조건 | 배포 체크리스트 (Dockerfile, Jenkinsfile, 빌드 성공, 이미지 배포 등) |
| 4. 범위 | 대상 서비스, 환경 (dev/staging/prod) |
| 5. 검증 방법 | Healthcheck, 버전 확인, API 호출 테스트 |
| 6. 참고 자료 | 이미지 태그, 환경 설정, 관련 이슈 |

**수집 정보:**
- 배경 (왜 필요한지)
- 작업 설명 (무엇을 빌드/배포하는지)
- 배포 체크리스트 항목 (선택)
- 참고사항 (선택 - 이미지 태그, 환경 설정, 관련 이슈)

---

### 2. 데이터 작업 (Task 타입)

**자동 라벨:** "task"

| 섹션 | 작성 가이드 |
|------|-----------|
| 1. 문제/배경 | 왜 이 데이터 작업이 필요한지 |
| 2. 목표/기대 결과 | 어떤 데이터를 처리하는지 |
| 3. 완료 조건 | 데이터 수집/전처리/라벨링/검증/저장 체크리스트 |
| 4. 범위 | 데이터 소스, 대상 데이터셋 |
| 5. 검증 방법 | 데이터 건수, 품질 기준, Null 비율 |
| 6. 참고 자료 | 데이터 소스, 포맷, 저장 위치 |

**수집 정보:**
- 배경 (왜 필요한지)
- 작업 설명 (어떤 데이터를 처리하는지)
- 추가 체크리스트 항목 (선택)
- 참고사항 (선택 - 데이터 소스, 포맷, 저장 위치)

## AC 생성 패턴 (Template-Specific)

> 원칙: AC 3~5개 이내로 유지. 가장 중요한 검증 포인트만 포함.

**빌드/배포:**
- [ ] CI 빌드 성공 및 이미지 배포 완료 → 결과물: 빌드 로그 {{ci_log_link}}
- [ ] {{environment}} 환경 Healthcheck 정상 (200 OK) → 결과물: 응답 로그 {{healthcheck_log}}
- [ ] 배포 버전({{release_version}}) 정상 반영 확인 → 결과물: 버전 스크린샷 {{version_screenshot}}

**데이터 작업:**
- [ ] 데이터 파이프라인 실행 완료 → 결과물: 저장 경로 {{storage_path}}
- [ ] 목표 데이터 {{record_count}}건 이상 수집 → 결과물: 데이터 경로 {{data_path}}
- [ ] 품질 기준 충족 (Null < {{null_threshold}}%) → 결과물: 품질 리포트 {{quality_report}}

**평가:**
- [ ] 평가 실행 및 결과 파일 첨부 → 결과물: 결과 파일 {{eval_result_file}}
- [ ] 목표 지표 달성 ({{metric_name}} ≥ {{threshold}}) → 결과물: 메트릭 결과 {{metric_result}}
- [ ] 결과 분석 리포트 작성 → 결과물: 리포트 {{report_link}}

**새로운 기능 개발:**
- [ ] 테스트 작성 및 통과 → 결과물: 테스트 결과 {{test_result}}
- [ ] 요구사항 기능 정상 동작 → 결과물: 테스트 증빙 {{test_evidence}}

**기능 개선:**
- [ ] 개선 전/후 비교 측정 → 결과물: 비교 리포트 {{comparison_report}}
- [ ] 목표 지표 달성 ({{metric_name}}: {{baseline}} → {{goal}}) → 결과물: 메트릭 {{metrics}}

**리팩토링:**
- [ ] 기존 테스트 전체 통과 → 결과물: CI 로그 {{ci_log}}
- [ ] 기능 동작 동일 (회귀 테스트 통과) → 결과물: 테스트 결과 {{regression_result}}

**리서치:**
- [ ] 조사 결과 문서 작성 → 결과물: 문서 링크 {{summary_doc_link}}
- [ ] 핵심 질문에 대한 답변 제시 → 결과물: Q&A 섹션 {{qa_section}}
- [ ] 다음 단계 Action Item 명시 → 결과물: 액션 아이템 {{action_items}}

**버그 수정:**
- [ ] 재현 시도 시 버그 미발생 → 결과물: 재현 테스트 결과 {{reproduction_test}}
- [ ] 재발 방지 테스트 추가 → 결과물: 테스트 ID {{test_case_id}}

**문서 작업:**
- [ ] {{section_name}} 섹션 작성 완료 → 결과물: 문서 링크 {{doc_link}}
- [ ] 관련자 리뷰 완료 → 결과물: 리뷰 코멘트/승인 {{review_evidence}}
- [ ] 최종 게시 완료 → 결과물: 게시된 문서 URL {{published_url}}

## 공통 AC 항목

코드 변경이 포함된 작업(새로운 기능 개발, 기능 개선, 리팩토링, 버그 수정 등)에는 AC에 **공통 섹션**을 추가합니다.

    ### 공통
    - [ ] 코드 리뷰 완료 → 이슈 리소스에 PR/MR 링크 첨부

**적용 규칙:**
- PR/MR이 필요한 작업에만 추가 (리서치, 평가 등 코드 변경 없는 작업은 제외)
- AC 항목 본문에 `→ 결과물: PR 링크 {{pr_link}}`를 넣지 않음
- PR/MR 링크는 이슈 리소스(links)로 첨부됨 → evidence 스킬이 `save_issue`의 `links` 필드로 추가
- validator는 이슈 `attachments`에서 PR/MR URL을 확인하여 검증

## 제목 개선 가이드라인

제목 공식: `[대상] + [행동] + [이유/효과]`

### 예시:

**빌드/배포:**
- Bad: "빌드" → Good: "RCA 에이전트 v2.0 개발 서버 배포"

**데이터 작업:**
- Bad: "데이터 작업" → Good: "Bank 데이터셋 전처리 및 라벨링"

**평가:**
- Bad: "평가" → Good: "RCA 모델 정확도 평가 (Acc@3)"

**기능 개발:**
- Bad: "기능 추가" → Good: "리포트에 CSV 내보내기 기능 추가"

**기능 개선:**
- Bad: "더 빠르게 만들기" → Good: "사용자 검색 데이터베이스 쿼리 성능 최적화"

**리팩토링:**
- Bad: "코드 정리" → Good: "인증 모듈 아키텍처 리팩토링"

**리서치:**
- Bad: "조사" → Good: "GraphQL vs REST API 성능 비교 조사"

**버그 수정:**
- Bad: "로그인 문제" → Good: "OAuth 사용자 로그인 실패 수정"

**문서 작업:**
- Bad: "문서 작성" → Good: "온보딩 매뉴얼: Confluence 문서 전면 리뉴얼 (기존 문서 링크 + 신규 섹션 작성)"

## 작업 템플릿 → 이슈 타입/라벨 자동 매핑

| 작업 템플릿 | Linear 이슈 타입 | 자동 라벨 |
|------------|----------------|----------|
| 빌드/배포 | Task | "build" |
| 데이터 작업 | Task | "task" |
| 평가 | Task | "task" |
| 새로운 기능 개발 | Feature | "feature" |
| 기능 개선 | Feature | "improvement" |
| 리팩토링 | Feature | "improvement" |
| 리서치 | Research | "research" |
| 버그 수정 | Bug | "bug" |
| 문서 작업 | Feature | "feature" (신규) / "improvement" (수정·개선) |

### 내용 기반 추가 라벨:
내용 분석을 통해 다음과 같은 추가 라벨 적용 가능:
- "backend" - 백엔드 관련
- "frontend" - 프론트엔드 관련
- "API" - API 관련
- "database" - 데이터베이스 관련
- "infrastructure" - 인프라 관련
- "security" - 보안 관련
- "performance" - 성능 관련
- "documentation" - 문서 관련
