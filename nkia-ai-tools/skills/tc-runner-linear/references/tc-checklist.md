# TC 작성 체크리스트 (NKIA 팀 모범 사례 + PIMS #120773 가이드 반영)

원본 가이드 — `references/good-tc-template.md` (PIMS #120773 첨부, 374줄). **작성 전 통독 권장.**
이 문서는 그 원본의 **요약 + 작업 룰** 빠른 참조용.

## 1. 작업 룰 (PIMS #120773 본문 발췌)

**한 PIMS 이슈 = 한 화면**. 화면 안의 탭별 데이터가 많이 다르면 **탭별 분리 이슈** 생성.

### 제목 형식
```
[<모듈>-<하위모듈>] <화면> > <탭> > <섹션>
예: [SMS-상세] 성능 > 메모리
예: [chat] 개인 대화 메모리 > CRUD
```

### 업무 범주 (PIMS category)
- `On-Premise <모듈명>` 형식으로 세팅.
- 모듈명이 PIMS category 목록에 없으면 **추가 X**. 카테고리 없이 만들고 나중에 수동 지정.

### 마일스톤
- "테스트자동화" 마일스톤 (fixed_version_id=`2096`) 에 묶는 것이 표준.
- `PIMS_FIXED_VERSION_ID=2096` 환경변수 또는 `--version=2096` 으로 지정.

### TC 단위 룰 (중요 — 가이드 직접 인용)

- **그리드 화면**:
  - 전체 컬럼 **정렬**은 **하나의 TC**. 안에 컬럼별 step 으로 나열. (개별 컬럼마다 TC 분리 X)
  - 전체 컬럼 **필터**도 **하나의 TC**. 안에 컬럼별 step.
  - 컬럼 수정 / Excel 다운로드 가 있으면 각각 TC.
- **차트 화면**:
  - 드롭다운 메트릭 선택/삭제는 별도 TC.
  - **Pin / 확대보기 / 공유노트 각각 분리된 TC**.
- **화면 전환 링크/버튼**: 각 기능별 화면 테스트 TC 추가.

### 결과 댓글 룰
- **화면 로딩 시간 ms 단위 필수** (예: `1010ms`).
- 업로드 전후 문자 깨짐/화면 깨짐 검증.

### 작업 방식 룰
- **팀 에이전트 방식 금지**. 단독 모델(좋은 모델)로 진행.
- 후반으로 갈수록 컨텍스트 누적으로 TC 빠뜨림 발생 — 한 모듈은 전체 TC 가 나올 때까지 대화하며 뽑아낼 것.

## ⚠️ 2.0 포맷 룰 — 본문 = markdown, 댓글 = textile (혼용 금지)

PIMS Redmine 은 본문(`description`)과 댓글(`notes`) 의 텍스트 포맷이 다를 수 있다.
이 스킬은 다음을 **반드시** 지킨다:

| 영역 | 포맷 | 헤더 | 표 |
|------|------|------|----|
| **본문 (description)** | **markdown** | `##` / `###` / `####` | `\| 항목 \| 내용 \|` + `\|---\|---\|` |
| **댓글 (note)** | **textile** | `h2.` / `h3.` | `\|. 항목 \|. 내용 \|` |

**본문에 다음이 있으면 자동 거부 → 재작성**:
- `h1.` / `h2.` / `h3.` 텍스타일 헤더
- `#### 사전조건` / `#### 참고사항` / `#### 테스트절차` / `#### 예상결과 (캡처포함)` 4종 헤더가 **TC 수만큼** 존재하지 않음
- `~~~` 블록이 **(TC 수 × 4 섹션 × 2)** 만큼 존재하지 않음
- 4섹션 본문이 `~~~` 블록 밖 평문으로 작성됨

**댓글에 다음이 있으면 자동 거부 → 재작성**:
- `##` / `###` 마크다운 헤더 (텍스타일이라 `h2.` / `h3.` 써야 함)
- `| ... | ... |` 마크다운 표 (텍스타일이라 `|. ... |. ... |` 써야 함)

> Step 3 (TC 초안 사용자 확인) 단계에서 위 룰 자체 검증 후 사용자에게 보여줄 것.
> Step 6 (결과 댓글 작성) 단계에서도 같은 검증.

## 2. 본문 markdown 구조 (한 PIMS 이슈)

```markdown
## <화면명> 테스트케이스

| 항목 | 내용 |
|---|---|
| 대상 화면 | <화면 경로> |
| Positive TC | N개 |
| Negative TC | N개 |
| 생성일 | YYYY-MM-DD |

---

### TC-<도메인>-001 - [<모듈>] <시나리오 요약>

#### 사전조건
~~~
- (실행 전 충족 상태. 없으면 "없음")
~~~

#### 참고사항
~~~
- (UI 자동동작·업무 규칙·화면 구조 힌트)
~~~

#### 테스트절차
~~~
1. (단일 동작)
2. ...
~~~

#### 예상결과 (캡처포함)
~~~
- 1. {무엇이} {어디에} {어떻게} 표시/변경된다  (절차 번호와 매핑)
~~~

---

### TC-<도메인>-002 - ...
(반복)

---

_AI 기반 자동 생성 도구에 의해 생성됨 (Good TC 템플릿 준수)_
```

> **헤더 레벨**: 묶음 제목 `##`, 개별 TC 제목 `###`, 4섹션 라벨 `####`. 4섹션 본문은 `~~~` 블록.

## 3. TC ID 형식

`TC-<도메인>-NNN` — 3자리 일련번호.

- `TC-NAMESPACE-001` (KCM 네임스페이스)
- `TC-MEMORY-001` (개인 대화 메모리)
- `TC-RCA-REPORT-001` (RCA 보고서)

## 4. Positive / Negative 비율

- **쌍 강제 아님**. 한 화면당 **Positive 다수 + Negative 소수** 가 표준.
- Negative TC 제목 끝에 `[Negative]` 표기.

## 6. 성능 측정 항목 (중요)

화면 로딩·드로어 로딩·차트 로딩·API 응답 시간을 **TC 안에서 측정해서 결과에 ms 단위로 기록**.

- 예상결과 문구에 굵게 명시: `**화면 로딩 시간이 측정되어 결과에 기록된다.**`
- 결과 댓글의 "성능 측정" 섹션에 별도 표:
  - `화면 로딩 시간: 1010ms`
  - `드로어 로딩 시간: 370ms`

## 7. 합격 기준 (등록 전 셀프 체크)

**포맷 (본문/댓글 혼용 금지 — §2.0 참조)**
- [ ] 본문에 `h1.`/`h2.`/`h3.` 텍스타일 헤더 **없음**
- [ ] `#### 사전조건` / `#### 참고사항` / `#### 테스트절차` / `#### 예상결과 (캡처포함)` 각각 **TC 수만큼** 존재
- [ ] `~~~` 블록 수 = TC 수 × 4 섹션 × 2
- [ ] 본문 표는 마크다운 `| ... | ... |`, 댓글 표는 텍스타일 `|. ... |. ... |`

**내용**
- [ ] 4섹션 모두 `~~~` 블록 안에 채움 (없으면 "없음")
- [ ] 절차 번호 1부터 연속, 각 절차 = **단일 동작**
- [ ] 절차 ↔ 예상결과 1:1 매핑
- [ ] 모호 부사 금지: "정상", "문제없음", "제대로", "잘", "올바르게"
- [ ] 예상결과는 **selector + 기대값** 으로 단언 가능한 관찰 서술
- [ ] 메뉴·버튼·필드 라벨이 lucida-ui 실제 값과 일치
- [ ] 데이터는 사전조건에 명시 (하드코딩 금지)
- [ ] 화면 진입/주요 인터랙션 TC 에 **로딩 시간 측정 (ms)** 포함
- [ ] 그리드 정렬·필터는 한 TC 안에서 컬럼별 step 으로
- [ ] 차트 Pin/확대보기/공유노트는 각각 분리된 TC
- [ ] 마지막에 `_AI 기반 자동 생성 도구에 의해 생성됨_` 푸터

## 9. 완성 예시 (모범 사례 PIMS #120248 발췌)

```markdown
### TC-NAMESPACE-001 - [KCM] 네임스페이스 목록 화면 접속 및 그리드 표시 확인

#### 사전조건
~~~
- KCM 모듈에 1개 이상의 네임스페이스 리소스가 등록되어 있음.
- 쿠버네티스 메뉴 접근 권한을 가진 사용자로 로그인 완료.
~~~

#### 참고사항
~~~
- 네임스페이스 목록 화면은 좌측 KCM 서브메뉴에서 "네임스페이스"를 클릭하여 진입한다.
- 데이터는 AG Grid(`div.ag-root`)로 표시되며, 무한 스크롤 방식으로 추가 로드된다.
- 컬럼 구성: 네임스페이스, 클러스터, 네임스페이스 상태, CPU 사용량, 메모리 사용량, 디플로이먼트 수, 서비스 수, 에이지
~~~

#### 테스트절차
~~~
1. 좌측 KCM 서브메뉴에서 "네임스페이스"를 클릭하고 화면 로딩 시간을 측정한다.
2. AG Grid(`div.ag-root`)가 렌더링되었는지 확인한다.
3. 그리드 헤더에 표시된 컬럼명을 확인한다.
~~~

#### 예상결과 (캡처포함)
~~~
- 1. 화면 URL에 KCM 관련 경로가 포함되고 AG Grid(`.ag-row`)가 렌더링된다. **화면 로딩 시간이 측정되어 결과에 기록된다 (ms 단위).**
- 2. AG Grid(`div.ag-root`)가 렌더링되고 `.ag-row` 요소가 1개 이상 존재한다.
- 3. `.ag-header-cell-text`에 네임스페이스, 클러스터, 네임스페이스 상태, CPU 사용량, 메모리 사용량, 디플로이먼트 수, 서비스 수, 에이지 텍스트가 각각 표시된다.
~~~
```
